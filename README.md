# SC REVIT

SC REVIT 是一套 Revit 2024 MEP 輔助工具集，目前以安裝包形式提供測試使用。  
目前請使用 GitHub Releases 下載安裝包，不要使用 GitHub 的 `Code > Download ZIP`。

目前公開安裝版為 `v0.5.3`。`main` 分支另含後續的 CAD 管徑分析、路網拓樸預覽與分段變徑開發成果；兩者內容並不完全相同。

## v0.5.3 版本狀態

目前公開基準包含 Revit 2024 排水接入幹管工作流程，以及經實機驗證的消防支管建立與系統類型統一流程：

- 以開放 piping connector 作為支管來源。
- 依序選取支管與目標主管。
- 立管使用來源側雙 45°、徑向管段及平面 45° 接入。
- 支援不同管徑與專案管件設定。
- 建立後檢查管件角度、接入方向、管段長度與拓撲。

本版同時修正 CAD 點位與消防支管預覽殘留、異常座標、螢光路徑顯示及消防管網連接／系統類型問題。

> `main` 是目前開發中的完整原始碼，不等同於上方 `v0.5.3` 安裝包。開發中更新請參閱 [更新紀錄](CHANGELOG.md)。

## 消防支管操作教學

### 操作流程

1. 在 Revit 選取一段消防主管，再開啟 `消防支管建立`。頁面會自動載入專案中的系統類型、管類型、樓層與已使用管徑，不需要另外按「讀取專案資料」。
2. 按 `讀取選取主管`，確認主管 Element ID、系統與管徑正確。
3. 設定支管的 `系統類型`、`管類型`、`樓層`、`支管距離樓層高度(cm)` 與高度基準。高度仍以樓層為基準，不會改用主管中心高度。
4. 回到 Revit 框選或多選要接管的撒水頭，再按 `讀取框選撒水頭`。確認清單中的 ID、族群、類型與座標。
5. 按 `分析並顯示預覽`。工具會讀取目前視圖中可見的 CAD 路徑與管徑證據，判定優先順序為「文字 → 線段顏色 → 圖層備援」，再產生同一份拓樸計畫供 SVG 與 Revit 建模使用。
6. 在分析結果中檢查 `管徑分段`、`水平沿程變徑` 與 `落水管規則`。需要定位時可雙擊項目，讓 Revit 視圖聚焦對應區域。
7. 按 `查看路網圖`，以縮放與拖曳方式核對主管、支管方向、交點、管徑、異徑及待確認項目。現階段 SVG 是計畫檢視器，尚不能直接修改拓樸。
8. 先執行 `建立前完整檢查（完成後自動復原）`。這項檢查只驗證建模與連通性，完成後不在模型留下管線。
9. 檢查通過後按 `正式建立消防支管`。若只有部分節點失敗，中文結果視窗會列出影響範圍，使用者可選擇保留成功部分或全部復原；保留後仍可使用 Revit Undo 回復。

```mermaid
flowchart LR
    A["Revit 選取主管"] --> B["開啟工具並自動讀取專案資料"]
    B --> B2["讀取選取主管"]
    B2 --> C["設定 System Type、Pipe Type 與樓層高度"]
    C --> D["框選撒水頭並讀取"]
    D --> E["CAD 管徑分析與拓樸計畫"]
    E --> F["檢查分段結果與 SVG 路網圖"]
    F --> G{"計畫是否可用"}
    G -- "否" --> C
    G -- "是" --> H["建立前完整檢查並自動復原"]
    H --> I["正式建立消防支管"]
    I --> J["驗證 Connector 與 MEP System"]
```

### 拓撲示意

同排撒水頭共用一支水平支管；支管再經垂直短管接到每顆撒水頭。主管交會處會依實際拓撲與管徑選擇可用的接頭，不以單一接頭方式套用所有情況。

```mermaid
flowchart TB
    M["既有消防主管"] --- J(("Tee／Cross／可用接頭"))
    J --- B["新建水平支管"]
    B --> D1["垂直短管"]
    B --> D2["垂直短管"]
    D1 --> S1["撒水頭 Connector"]
    D2 --> S2["撒水頭 Connector"]
```

目前 `main` 已能依 CAD 證據規劃分段管徑與異徑，但尚未支援 L／U／雙 L 型複合主管、直接編輯 SVG 拓樸或自動避梁。這些後續方向記錄於 [消防支管複合主管、拓樸修正與自動避梁計畫草案](docs/fire_branch_compound_routing_and_beam_avoidance_plan.md)。螢光線只是暫存預覽；重新預覽、完成建立、取消流程或關閉工具視窗時，系統會在背景清除 SC REVIT 建立的預覽元素與未使用群組類型。

| 圖示 | 按鈕 | 用途 |
| --- | --- | --- |
| <img src="docs/user-guide-assets/drainage_connect.png" width="44" alt=""> | 排水接入幹管 | 依提示先選來源，再選這一支要接入的主管；成功後可繼續下一支。 |
| <img src="docs/user-guide-assets/drainage_settings.png" width="44" alt=""> | 管件設定 | 依目標 Pipe Type／System Type 設定斜 T／Y、彎頭、變徑、坡度與管徑範圍。 |
| <img src="docs/user-guide-assets/align_centerline.png" width="44" alt=""> | 管中心對齊 | 先選非垂直的高程基準管，再連續對齊其他管段的局部中心線高程。 |

`45度對接`、`向下45°` 與 `垂直向下` 目前不在 Ribbon 上，不應再依舊手冊尋找這三個按鈕。

### 最短操作流程

1. 展開 `排水接入幹管`，先進入 `管件設定`。
2. 選擇目標 Pipe Type 與 System Type，新增設定列並確認管件、管徑及坡度後儲存。
3. 執行 `排水接入幹管`。
4. 依 `1/2` 提示點選設備接口或開放管端。
5. 依 `2/2` 提示明確點選本支要接入的主管。
6. 成功後直接繼續下一支；單支失敗會回復該支並顯示處理方式。
7. 按 `Esc` 結束整輪操作；成功結果合併為一次 Revit Undo。

## 安裝與更新

需求：Windows 10／11、Autodesk Revit 2024。使用者不需要安裝 Python、Visual Studio 或自行編譯。

1. 從上方「快速下載」取得 installer ZIP，並完整解壓縮。
2. 關閉 Revit 2024 與所有 SC REVIT 視窗。
3. 執行 `Install_SC_REVIT.bat`。
4. 安裝完成後重新開啟 Revit，在 Ribbon 找到 `SC 族群工具`。

同一個安裝檔同時支援首次安裝與覆蓋更新，不需先移除舊版。第一次載入若 Revit 顯示未簽章警告，確認名稱為 `SC REVIT` 與下載來源正確後再允許載入。

## 基本使用方式

安裝完成並重新啟動 Revit 後，開啟 `SC 族群工具` Ribbon。  
目前主要工具包含：

- `族群歸檔`（**開發中**）：整理與歸檔 Revit 族群。
- `專案回收`（**開發中**）：掃描專案內族群，準備回收整理。
- `批量點位放置`：從 CAD / DWG block 點位批量放置 Revit 元件。
- `SC 後台`：查看工具操作紀錄、建立結果與後續管理狀態。
- `開孔定位`（**開發中**）：檢查 MEP 與建築連結物件，產生開孔候選。
- `消防支管建立`：依候選主管與撒水頭位置，輔助建立垂直於最近主管的消防支管。
- `身份檢查`（**開發中**）：檢查選取元件是否具備後台追蹤所需身份資料。
- `參數健檢`（**開發中**）：檢查 SC_ 參數缺漏與空值。
- `斷點檢查`（**開發中**）：診斷 pipe / duct / conduit 連接狀態，只對可修復 pipe 執行自動修復。
- `管支撐預覽`（**開發中**）：依選取 pipe 產生支撐候選點預覽。
- `排水接入幹管`：依序選取開放支管端與目標主管，建立符合專案設定的排水接管。
- `管件設定`：依 Pipe Type 設定斜 T／Y、45°彎頭、變徑及排水坡度。

## 常見問題

### 看不到 Ribbon

- 確認已重新啟動 Revit。
- 重新執行 `Install_SC_REVIT.bat`。
- 確認目前使用的是 Revit 2024。

### Revit 卡頓、無回應或需要回報問題

1. 關閉 SC REVIT 視窗與 Revit。
2. 重新開啟 Revit，確認是否可重現。
3. 執行安裝目錄內的 `收集_SC_REVIT_診斷資料.bat`，將桌面產生的診斷 ZIP 交給開發者。

### 點工具後沒有資料

部分工具依賴目前 Revit 模型狀態。  
例如 CAD 點位需要模型中有 CAD Link / DWG，管線檢查需要先選取 pipe / duct / conduit。

## 給開發者

這個 public repo 同時保存可下載安裝版的版本說明，以及目前公開的開發原始碼。`v0.5.3` tag 對應公開安裝包；`main` 可能包含尚未重新發布 installer 的更新。
消防支管已在目前指定專案完成實際建立，但不同專案的族群 Connector、管件與系統設定仍可能不同，正式批次使用前應先執行建立前完整檢查。

開發者打包新版 installer 時，請使用專案內的 release 打包腳本產生 installer ZIP，再上傳到 GitHub Releases。
