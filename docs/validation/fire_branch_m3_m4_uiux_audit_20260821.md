# M3/M4 UI/UX 稽核（2026-08-21）

## 範圍

本次只檢查消防支管的 M3「拓樸計畫呈現」與 M4「有限計畫修正」：

- 不修改 Revit 建模核心、主管／支管建立順序或灑水頭落水管邏輯。
- 只改善 GUI 的閱讀、選取回饋、計畫狀態、修正入口與預檢提示。
- GUI 仍以同一份 `topology_plan` 作為 SVG 預覽與後續建模的共同資料來源。

## 證據與限制

目前可取得的證據是原始碼、既有回歸測試及本次來源盤點。嘗試擷取目前 Windows 桌面時，`CopyFromScreen` 回傳「控制代碼無效」，產出的黑色影像已判定為無效證據，不納入視覺結論。因此本報告不宣稱已完成目前 Revit 視窗的逐像素驗收；實機字體與縮放仍需使用者在更新 GUI 後確認。

## M3/M4 改版目標

1. 任何時刻都能看到：分析狀態、計畫版本、CAD 核對狀態、目前選取與下一步。
2. 字體與列高以 11pt/30px 為消防工作區的最低可讀基準；縮小視窗時優先保留資訊，不讓按鈕重疊。
3. 使用者選取列、管段、接頭或異徑後，固定區域顯示對象名稱、ElementId／計畫 ID、管徑、長度與判定依據。
4. M4 每次修改先更新本地計畫，再可立即按「檢查目前計畫」；未通過時顯示中文問題清單，不能進入 Revit 預檢。
5. 不改建模器；只有通過計畫驗證的資料才送往既有 Revit 預檢／建模流程。

## 驗收條件

- 主 GUI 的消防區塊在 1360×820 與較窄視窗都能讀到狀態、選取摘要、管徑表與四個主要動作。
- 路網編輯器能在不重開 Revit 的情況下修改計畫、Undo/Redo、顯示 revision/hash，並用同一個 `validate_topology_plan` 回報中文結果。
- 任一無效修改都只停在計畫層，不改模型、不清除成功的既有預覽。
- 現有消防與拓樸測試全部通過；新增測試覆蓋字體 token、選取摘要、計畫檢查結果與 M4 控制項分組。

## 本輪實作結果

- 主 GUI 已將消防工作區最低字體提高到 11pt，Treeview 列高提高到 30px；區段標題、狀態與提示使用不同層級，避免所有文字看起來一樣重要。
- 右側改為「目前模式／計畫狀態／分析摘要／結果表／主要動作」的順序；新增固定的撒水頭、管段與異徑選取回饋，會顯示 ElementId、管徑、長度與判定依據。
- 完整分析報告改成「摘要／計畫資訊／候選與異常」三個分頁，並可複製完整報告；不再把關鍵資訊藏在單一長字串。
- M4 路網編輯器已將管徑、接頭、異徑與候選路徑分組，新增「檢查目前計畫」及中文檢查結果；畫布單擊可回選管段、接頭或異徑，計畫套用後立即重新檢查。
- `python -m py_compile gui_app.py sc_revit/fire_branch/network_preview.py` 通過；`python -m unittest discover -q` 共 267 項測試通過。
- 尚未部署 DLL、重開 Revit 或執行活動模型建置；本輪只完成 GUI／計畫編輯器與自動化測試，實機視覺驗收仍需另行執行。
