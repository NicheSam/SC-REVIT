# 消防支管落水變徑建模規劃

## 目標

把目前只用於分析與 SVG 預覽的管徑結果，轉成可在 Revit 沙盒建立、驗證並回復的建模計畫。第一版只處理已確認的水平支管、灑水頭落水管與變徑規則，不同時擴充其他拓樸。

## 已確認工程規則

1. 水平支管的沿程變徑若與灑水頭接管點相鄰，實際變徑位置在三通之後，不與三通重疊。
2. 接到灑水頭 Connector 的落水段固定為 DN25（1 吋）。
3. 三通垂直出口先保留與接入位置水平支管相同的管徑，再放置落水變徑，最後以 DN25 接至灑水頭。
4. 水平支管本身為 DN25 時，不建立多餘的落水變徑。
5. 垂直或水平空間不足時列為不可建立，不以重疊管件或放寬連接驗證強制通過。

## 建模計畫介面

分析端只輸出一份 `FireBranchModelPlan`，GUI、沙盒建立與正式建立都使用同一份計畫，不分別重算規則。

每個灑水頭的計畫至少包含：

- 灑水頭 ElementId。
- 水平支管與接管點。
- 接管點上游、下游與三通出口管徑。
- 是否需要水平沿程變徑。
- 是否需要落水變徑。
- DN25 落水段的起終點。
- 可用水平、垂直空間與不能建立的原因。
- 計畫識別碼，供沙盒結果與正式建立核對是否為同一版。

## 模組切分

### 1. 建模計畫模組

輸入 CAD 管徑分析、Revit 支管路徑與灑水頭位置，輸出純資料計畫，不修改 Revit。

它負責：

- 把 CAD 的邏輯變徑點轉為不與三通重疊的實際配置順序。
- 固定 DN25 落水段。
- 判斷是否需要水平變徑與落水變徑。
- 先找出空間不足、缺少管徑或拓樸不明的項目。

### 2. Revit 建模執行模組

只接受已完成的 `FireBranchModelPlan`，不自行推測 CAD 管徑。

每個非 DN25 落水組件的建立順序：

1. 建立與水平支管同徑的三通出口短管。
2. 從灑水頭 Connector 建立 DN25 落水段。
3. 在兩段管的開放 Connector 間建立 Transition。
4. 將三通出口短管接入水平支管 Tee。
5. `Regenerate` 後核對每個 Connector、管徑與系統類型。

DN25 水平支管直接建立 DN25 落水管與 Tee，不建立 Transition。

### 3. 管件空間求解

「往下一點點」不使用單一固定距離。Revit 沙盒依目前 Pipe Type 的 Routing Preferences 與實際 Transition 族群，嘗試最短可用配置；成功後讀回管件外形與 Connector 位置，形成可提交的實際尺寸。若找不到不重疊且可連接的配置，該灑水頭不可提交。

SVG 中的短管長度只依三通節點、變徑符號外框與最小視覺間隙排版，僅用來避免圖示重疊。不得將 SVG 像素距離換算成 Revit 管長；正式建模距離只能採用沙盒讀回的管件 Connector、外形尺寸及碰撞驗證結果。

## 實作階段

### 階段一：純計畫與 GUI 預覽

- 新增 `FireBranchModelPlan` 與 `DropAssemblyPlan`。
- SVG 顯示水平變徑、Tee、三通出口短管、落水變徑與 DN25 落水段。
- GUI 顯示每個灑水頭是「直接 DN25」或「需要落水變徑」。
- 不呼叫 Revit 建立。

完成門檻：已知範例能清楚顯示 `DN40 Tee → DN40 短管 → DN40×DN25 變徑 → DN25 落水段`，且水平變徑位於 Tee 之後。

### 階段二：單一灑水頭沙盒

- 一次只對一顆灑水頭建立完整落水組件。
- 使用 SubTransaction 嘗試不同最短間距。
- 整體 TransactionGroup 最後 Rollback。
- 記錄管件族型、實際短管長度、Connector 狀態與失敗原因。

完成門檻：DN25、DN32 與 DN40 水平支管各至少一例通過；測試後模型元素數量不變。

### 階段三：單排支管沙盒

- 加入水平沿程變徑。
- 驗證變徑與 Tee 的先後順序。
- 驗證相鄰灑水頭、短管長度與管件碰撞。

完成門檻：整排所有管段、Tee、Transition 與灑水頭 Connector 均連通，系統類型一致，Rollback 後無殘留。

### 階段四：整批沙盒與正式提交門檻

- 使用目前所有選取灑水頭執行整批沙盒。
- 沙盒結果保存計畫識別碼與完整驗證結果。
- 正式建立前重新讀取模型；選取、管型、系統型、CAD 分析或計畫識別碼任一改變，就要求重新沙盒。

完成門檻：零未連接 Connector、零錯誤管徑、零錯誤系統、零重疊管件，且正式按鈕只在同一份計畫通過沙盒後啟用。

## 主要風險

- Pipe Type 缺少可用的 Transition 或 Tee Routing Preferences。
- 不同變徑族的實際長度不同，不能用固定短管長度通吃。
- 灑水頭 Connector 方向、標高或宿主不同，可能沒有足夠垂直空間。
- CAD 邏輯變徑點可能正好落在 Tee 中心，必須轉為 Tee 後的實際管件配置位置。
- 同一排相鄰接管點過近，可能無法同時容納 Tee 與水平 Transition。

## 第一個實作切片

先實作「一顆灑水頭、單一直線水平支管、支管管徑 DN32 或 DN40、落水轉 DN25」的沙盒流程。暫不包含水平沿程變徑；確認落水組件可靠後，再把水平變徑接入同一份建模計畫。
