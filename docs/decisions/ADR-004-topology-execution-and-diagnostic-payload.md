# ADR-004：拓樸計畫直接執行與完整診斷資料

## 狀態

採用，2026-08-17。部分取代 ADR-003。

## 背景

消防支管的 SVG 已確認拓樸交點與管徑，但 Revit 執行端仍以灑水頭投影重新計算支管交點，直到建立四通時才改用 `topology_plan` 的交點。兩套座標可落在既有 50 mm 容差內，卻仍讓四條管端與實際四通位置不完全一致。

`NewCrossFitting` 也可能依 Routing Preferences 自動加入合法的 Transition。舊驗證只接受管端直接引用四通，因此會拒絕實際可連通的管件路徑。

批次資料庫只保存 4000 字摘要。消防拓樸 payload 超過此長度後，完整 junction、座標與管徑資料被截斷，無法重播失敗要求。

## 決策

1. `topology_plan` 是 SVG 與 Revit 建模共同且唯一的建置計畫。
2. 支管幾何建立前就以計畫交點決定端點；C# 不得在建模階段重新推算四通交點。
3. 四通完成後驗證管端是否可經純 Pipe Fitting 短路徑到達計畫四通。允許 Revit 自動插入的合法 Transition，但不允許經其他 Pipe 繞路。
4. 最終驗證仍由主管遍歷整個實體 Connector 圖，核對灑水頭可達性、管徑順序與系統類型。
5. 完整成功時，測試模式自動 Rollback、正式模式提交為單一 Undo。局部失敗依 ADR-006 顯示中文摘要，由使用者選擇保留成功部分或全部復原。
6. `request_summary` 與 `response_summary` 維持短摘要；完整 JSON、SHA-256 分別保存於獨立欄位，不再用摘要代替可重播資料。

## 後果

- 預覽、建置與診斷使用同一份拓樸資料。
- Revit 合法自動轉接不再被錯誤的直接相鄰檢查否決。
- 失敗 request 可以由資料庫完整還原及比對計畫雜湊。
- 完整 payload 會增加資料庫容量，後續需另訂保存期限；不可再以截斷關鍵資料控制容量。
