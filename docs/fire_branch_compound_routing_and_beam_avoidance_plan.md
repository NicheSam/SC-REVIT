# 消防支管複合主管、拓樸修正與自動避梁計畫草案

## 狀態

- 狀態：草案，尚未實作
- 日期：2026-08-17
- 適用範圍：SC REVIT 消防支管建立
- 原則：拓樸計畫是 SVG 預覽與 Revit 建模的唯一共同來源
- 詳細實做與 Luna 交接規格：`docs/fire_branch_luna_implementation_plan.md`

## 已確認決策

1. 主管可能是直線、L 型、U 型或雙 L 型，也可能包含彎頭與主管異徑。
2. 使用者選取一段主管作為搜尋種子；外掛沿實際 Connector 與管件展開主管路網。
3. 支管先依接入主管段的局部方向產生候選，再以 CAD 路徑圖確認完整複合路徑。
4. SVG 將升級為受限制的拓樸計畫編輯介面，只允許小幅且可驗證的修正。
5. 高度設定維持目前流程：保留「支管距離樓層高度」與既有高度基準，不改由主管中心高度換算。
6. 自動避梁延用 SC REVIT 開孔定位的 Link 座標與結構碰撞基礎，並參考 Issue #99 的 `review_required` 分流原則。
7. 本草案不改變灑水頭位置；灑水頭位置是固定端點。
8. 主管經三通或四通時，依「同系統且實際連通 → 同管徑且最接近原方向 → 最大管徑 → 最大管徑中轉折最小」判斷；仍有多解時標記待確認。
9. 同一撒水頭存在多條接管候選時，以 CAD 路徑證據完整度為主，距離只作最後同分條件。
10. SVG 修改只代表拓樸意圖；修改後必須重新通過拓樸檢查、Revit 配件預檢及可回復沙盒，才能標記為可正式建立。
11. 第一版自動避梁只處理支管與結構梁，採四個 90° 彎頭下繞；不改主管、不變徑，也不檢查其他 MEP。
12. 無 CAD 底圖流程使用獨立的「無 CAD／統一管徑」頁籤，但與 CAD 模式共用同一套 Revit 建模與驗證核心。

## 目標流程

```text
選取主管種子
  → 建立 MainRunGraph
  → 讀取撒水頭與可見 CAD
  → 建立 CAD Route Graph
  → 產生多組支管候選
  → 管徑與管件判定
  → 產生 TopologyPlan
  → SVG 檢查／小幅修正
  → 結構障礙與避梁檢查
  → 產生 ExecutionPlan
  → Revit 沙盒建立與驗證
  → 正式建立
```

## 第一階段：複合主管路網

### MainRunGraph

每一段主管記錄：

- Pipe ElementId、起點、終點、局部方向及中心高度。
- Pipe Type、System Type、管徑及工作集等識別。
- 上下游 Connector 與相鄰彎頭、直接、異徑、三通或四通。
- 來源是使用者直接選取，或由主管種子自動延伸取得。

### 展開及停止規則

- 沿同系統且實際連通的 Pipe／Fitting 展開。
- 彎頭、直接與主管沿線異徑可以繼續。
- 遇到設備或灑水頭停止。
- 遇到三通或四通時，先選擇同管徑且最接近進入方向的出口；若沒有，再選最大管徑；最大管徑仍有多個時選轉折最小者。
- 四通中位於同一直線且同管徑的兩側可共同形成主管；其他出口列為支管候選。
- 多條路徑同樣合理時不得猜測，改標記為主管方向待確認。
- 不以固定角度或固定管徑作為唯一主管判定條件。
- 每個節點的原方向是從主管種子走到該節點時的局部進入方向，不是整個模型的固定方向。

## 第二階段：CAD 複合支管路徑

### CAD Route Graph

將目前可見且已完成 Revit 座標轉換的 CAD 路徑整理為圖：

- 節點：線段端點、交點、轉折點、主管接入點與灑水頭端點。
- 邊：CAD 線段幾何、圖層、顏色、鄰近文字及管徑證據。
- 方向：沿用 Revit 視圖的東西南北，不為 SVG 排版任意旋轉。

### 候選選擇

- 從每一個合理主管接入點產生局部垂直接出候選。
- 後續路徑沿 CAD Route Graph 搜尋，可包含一個或多個轉折。
- 即使只選取末端撒水頭，也必須保留途中所有 CAD 轉折、交點與管徑變化，不得只產生單一管徑直線。
- 候選依完整連通、CAD 重合比例、管徑證據完整度、交點與方向合理性、非管路雜訊比例、轉折數及路徑長度依序比較。
- 幾何距離最近不等於最終選擇；距離相近且證據衝突時標記待確認。
- SVG 以實線顯示選定路徑、淡色虛線顯示替代候選，並提供文字、顏色、圖層與幾何吻合依據。

## 第三階段：TopologyPlan 與 SVG 編輯

SVG 不直接保存建模資料，只顯示 TopologyPlan。所有修改都必須先寫入計畫，再重新產生 SVG 與 ExecutionPlan。

允許的修正：

- 在已計算的替代 CAD 路徑間切換。
- 修改單一管段管徑。
- 選擇合法的三通、四通、彎頭、直接或異徑意圖。
- 修改異徑前後管徑及同一管段內的合法放置位置。
- 修正支管的主管接入段。
- 合併或分離誤判的鄰近交點。

限制：

- 管徑只能從目前 Pipe Type 允許的尺寸中選擇。
- 管件只能從目前 Routing Preferences 可用的配置中選擇。
- 三支管線交點不能直接指定為四通。
- 每次修改後重新驗證方向、連通、管徑順序、管件空間及計畫雜湊。
- 若修改改變主管路徑、整排支管或多個相鄰交點，應重新分析，不以大量人工修改掩蓋演算法問題。

### 修改後的 Revit 可行性

SVG 修正後依序執行：

1. 拓樸檢查：連通、出口數、管徑順序、異徑位置、零長度及重疊管段。
2. Revit 配件預檢：Pipe Type 可用管徑、Routing Preferences、實際 Connector、最短管段與管件空間。
3. Revit 沙盒：由修改後的 TopologyPlan 產生 ExecutionPlan，實際建立、驗證並完整回復。

計畫狀態分為尚未驗證、拓樸有效、Revit 可建立及建立不可行。只有 Revit 沙盒通過的版本可以正式建立；失敗時必須在 SVG 標出節點、中文原因與合法替代方案。

## 第四階段：高度設定

本草案不修改目前高度算法與 GUI：

- 保留「支管距離樓層高度」。
- 保留目前的管上端、管中心與管下端高度基準。
- 預覽與正式建模必須共用同一高度輸入及換算結果。
- 灑水頭位置不移動，垂管由水平支管接到實際灑水頭 Connector。

## 第五階段：自動避梁

### 可延用的開孔定位能力

- Revit Link 與 `GetTotalTransform()` 座標轉換。
- 梁、柱、牆及樓板 Solid 讀取。
- BoundingBox 粗篩。
- 路徑與 Solid 交集、Host ElementId 與碰撞位置。

開孔定位輸出的是穿越候選；自動避梁還必須增加自由空間搜尋與替代路徑產生，兩者不能視為同一功能。

### 共用模組

```text
StructuralObstacleQuery
  ├─ 開孔定位：碰撞 → 開孔候選
  └─ 消防支管：碰撞 → 避梁候選
```

### 避梁判定

檢查範圍不能只使用管中心線，必須包含：

- 管外半徑。
- 保溫厚度。
- 專案要求的施工淨距。
- 彎頭、異徑及接頭需要的實際安裝空間。

第一版只處理水平支管與結構梁的碰撞，不檢查其他 MEP，也不對主管產生避梁候選。替代路徑固定為：原高度水平管、90° 向下、梁下水平管、90° 向上，通過梁後回到原高度與方向；完整配置共使用四個 90° 彎頭，全程維持原管徑。

梁下支管中心高度依下式計算：

```text
梁下支管中心高度
= 梁底高度
- 使用者設定的管頂淨距
- 管外半徑
- 保溫厚度
```

GUI 保留「管頂距梁底淨距」欄位，預設 5 cm，但不得寫死於演算法。梁前下降點與梁後上升點依梁 Solid、管徑、彎頭實際尺寸、Routing Preferences 及 `Application.ShortCurveTolerance` 求得，不使用固定長度。

相鄰梁之間若無法容納完整上升、水平短管及再次下降，應合併為同一個下繞區段，通過最後一支梁後才回到原高度。找不到合法下繞空間時標記人工確認，不改主管、不變徑，也不自動改用 45°。

### Issue #99 邊界

Issue #99 的結論保留：梁穿越屬於 `review_required`，不能因幾何掃描成功就自動開孔或自動建模。第一版避梁只產生候選與預覽，不直接修改模型。

## 第六階段：無 CAD／統一管徑模式

GUI 增加獨立頁籤，供沒有 CAD 底圖或不需要分段管徑分析的專案使用：

- 使用選取主管、選取撒水頭、System Type、Pipe Type、樓層、支管距離樓層高度及使用者指定的統一管徑。
- 不讀取 CAD、不判斷文字／顏色／圖層、不產生沿程異徑。
- 沿用既有直線支管分排與接管方式。
- 與 CAD 模式共用 Connector 連接、管件建立、中文診斷、局部保留、完整復原及 Revit 沙盒驗證。
- 不另行維護第二套建模核心；兩種模式只在 TopologyPlan 的產生方式不同。

## 實作順序與驗收

1. **主管路網唯讀分析**：L／U／雙 L 主管能由單一種子展開，且不誤納支管。
2. **CAD 複合路徑預覽**：路徑轉折、交點及方向與 CAD／Revit 視圖一致。
3. **TopologyPlan v4**：SVG 與 ExecutionPlan 使用同一份路徑、管徑與管件配置。
4. **SVG 小幅修正**：修改可追蹤、可復原，且每次都重新通過拓樸、配件及 Revit 沙盒驗證。
5. **複合路徑 Revit 沙盒**：建立後驗證 Connector、系統、管徑、異徑方向、異常長度及完整回復。
6. **無 CAD／統一管徑頁籤**：沿用共同建模核心，驗證不讀 CAD 時的舊版直線支管流程。
7. **障礙唯讀分析**：只針對支管，以計畫路徑及實際淨空包絡找出梁碰撞。
8. **單支管下繞候選**：先在一支管與一支梁上驗證四個 90°、梁下淨距及完整回復。
9. **相鄰梁合併下繞**：驗證多梁區段不反覆升降。
10. **整批路網**：單支管通過後才擴大，不以使用者反覆測試取代沙盒驗證。

## 尚待工程確認

- 梁與管線的施工淨距及保溫厚度來源。
- 允許的最大下降量、天花高度及其他禁入空間。
- 無法下繞時是否只回報人工處理，或在後續版本增加開孔候選銜接。
