# 第五階段：從目前專案回收已載入族群

## 狀態
規劃中

## 目標
在 Revit 專案檔開啟時，掃描目前專案中「已載入」與「實際使用」的可載入族群，讓使用者挑選值得回收的項目，另存為 RFA 後進入既有流程：

```text
專案掃描 → 候選清單 → 使用者挑選 → 匯出 RFA → 分類 → 命名 → 標準化 → 入庫
```

## 原則
- 不自動把專案內全部族群吞進公司庫。
- 只處理可載入族群；系統族群先列為不可回收項目。
- 專案來源族群視為候選資源，必須經過使用者確認。
- 回收出的 RFA 仍走現有分類器規則，不直接寫入正式庫。

## 第一版功能範圍
1. 掃描目前開啟的 Revit 專案。
2. 分成兩類：
   - 已載入族群
   - 實際有放置實例的族群
3. 顯示候選清單：
   - 族群名稱
   - Revit 主類別
   - 是否已使用
   - 使用數量
   - 是否可編輯／可回收
4. 使用者勾選要回收的族群。
5. 將勾選族群另存到暫存回收區。
6. 自動送進既有分類、命名、標準化、入庫流程。

## 不納入第一版
- 系統族群回收，例如牆、樓板、風管、管線類型。
- 自動判斷專案族群品質好壞。
- 自動覆蓋公司庫既有族群。
- 回寫專案中的族群。

## 技術邊界
- Revit API 可以用 `FilteredElementCollector` 掃描元素與族群。
- 可載入族群可透過 `Document.EditFamily(Family)` 開成獨立族群文件。
- 被開成族群文件後，可另存成 RFA，再交給目前分類器。
- 不可編輯、就地族群、系統族群不能用同一條流程處理。

## 建議 UI
在現有 GUI 新增一個分頁：

```text
專案回收
├─ 掃描目前專案
├─ 篩選：全部 / 已使用 / 未使用 / 可回收 / 不可回收
├─ 候選族群表格
│  ├─ 勾選
│  ├─ 族群名稱
│  ├─ Revit 主類別
│  ├─ 使用數量
│  └─ 狀態
└─ 匯出並送入分類器
```

## 風險
- 專案內族群可能是一次性特製品，不一定適合作為公司標準。
- 同名族群可能跟公司庫既有族群不同內容。
- 大型專案掃描需避免卡住 Revit UI。
- 部分族群可能不可編輯，必須清楚標示原因。

## 下一步
先做「只讀掃描」：
1. Revit 外掛新增 `scan_project_families` queue action。
2. GUI 新增「專案回收」分頁。
3. 只顯示候選清單，不匯出、不入庫。
4. 確認清單可信後，再做匯出 RFA。
